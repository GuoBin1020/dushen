# 联机卡密与联机代码加密 设计

## 1. 为什么做

赌神智慧树是给朋友娱乐、学习用的，作者不希望它被陌生人拿去联机赌博，从而带来法律风险。仓库要保持公开，所以需要做到两点：
- 只有作者发了卡密的人才能使用联机；
- 公开的仓库里没有能直接使用的联机代码。

## 2. 目标

1. 单机模式完全不变，不需要卡密。
2. 第一次创建或加入联机房间时，要求输入卡号和卡密。验证通过后才能继续。
3. 卡号和卡密由作者在自己的生成器页面生成：
   - 卡号由作者手动输入，内容随意；
   - 有效期在生成时设置。
4. 卡号和卡密保存在 localStorage，过期时间和有效期一致；过期后失效，需要重新输入新卡。
5. 联机核心代码（现在的 `js/net.js`，包括互联网和局域网）加密存放。解密用的密钥 K 放在生成器里，生成器把 K 写进每一张卡密。没有有效卡密，就拿不到能运行的联机代码。
6. 联机时房主和客人互相检查对方的卡密，任何一方无效或过期都进不了房间。
7. 看了全部源代码也无法生成有效的卡密。

## 3. 不做的事和限制（用户已知）

- 拿到过有效卡密的人，可以从卡密里取出 K，从而得到解密后的联机代码，并删掉有效期检查。本方案防的是陌生人，防不了作者发过卡的人。
- 没有服务器，所以不能让某张卡提前作废，只能等它到期。K 泄露时，可以换新的 K、重新加密并发布新版本；但已经流出的旧版本仍然能用。
- 卡密永远免费，不能收费。
- 联机时各人的卡号和卡密会发给同桌的其他人用来互相检查，所以拿到卡的朋友能从别人那里抄到卡密（包括有效期更长的卡）。这和「拿到卡的人能取出 K」属于同一种限制：只有作者发过卡的人能这么做。
- 已经发给朋友的单文件 HTML 和以前部署的网页里有明文联机代码，会一直能用，无法收回。

## 4. 卡密

- **密钥**【我定的】：
  - 签名用 Ed25519，生成器存私钥，游戏里只放公钥；
  - 联机代码用 XSalsa20-Poly1305（NaCl secretbox）和 32 字节密钥 K 加密。
  - 用户选了「内置加密库兜底」。为了让所有环境走同一套代码，签名、验证和解密都用打包进来的 TweetNaCl（公有领域许可，约 30KB），放在 `js/vendor/nacl.min.js`，和 PeerJS 一样不依赖网络，也不依赖浏览器自带的加密功能（微信内置浏览器、手机文件管理器里直接打开也能用）。下载这个库时说明来源和大小。
- **卡号**：
  - 作者手动输入的任意文字，最长 32 个字符；
  - 不能包含换行和 `|`；
  - 首尾空格会去掉。
- **卡密**【我定的】：
  - 内容是 `到期时间(4 字节，Unix 时间的分钟数) + K(32 字节) + 签名(64 字节)`，用 base64url 编码，大约 134 个字符；
  - 签名的内容是 `dushen-card-v1|卡号|到期时间|K 的 base64url`。
  - 改动卡号、有效期或 K 中的任何一样，签名都会失效。
- **有效期**：
  - 生成器里可以填天数，或者选具体的到期日期和时间，到分钟；
  - 到期以设备时间为准。
- **防止调回时间**【我定的】：
  - localStorage 记录「这台设备上见过的最晚时间」；
  - 如果当前时间比它早 10 分钟以上，判定卡密失效，并提示「设备时间被调回」。
  - 调回时间只是暂时挡住，不删除保存的卡；把时间改对就能继续用。
  - 输入一张新的有效卡时，把「见过的最晚时间」重置为当前时间，所以时钟曾经被调快过的设备不会被永久锁住【我定的】。重新粘贴同一张卡不会重置。
- 卡号按 NFC 规范化，不能有隐形字符、方向控制字符和孤立的代理项，避免两张卡在大厅里看起来一样。
- **保存**：
  - localStorage 的 `dushen-card` 里保存 `{no, secret, exp}`；
  - 只保留一张卡，输入新卡会覆盖旧的；
  - 页面打开时如果发现已经过期，就删除这条记录。

## 5. 联机代码加密

- **拆分 `js/net.js`**：
  - `js/net-core.js`（明文，单机也要用）：
    - `NET` 对象、`CID`、`roomIdentity`、`purgeIdentities`；
    - `cleanName`、`uniqueName`；
    - `ROOMLOCK` 和 `claimRoom`、`takeoverRoom`、`releaseRoom`；
    - `LOBBY`、`GL`；
    - `hostSave`、`saveSession`、`slimT`、`leaveAll`。
  - `js/net-online.js`（加密，只存在作者本机）：PeerJS 和局域网连接、`openHostPeer`、`restoreHost`、房主和客人的消息处理、`hostStart`、`lobbySync`、`lobbyChat`、局域网连接码、客人加入和重连。
  - 具体每个函数放哪边【留给实现者】，但单机模式（各个游戏、教练、结算、设置页）不能依赖加密部分。
- **公开仓库里只有** `js/net-online.enc.js`，格式是 `window.DUSHEN_SEALED={v:1,n:'…',ct:'…'}`（secretbox 加密后的源码，`n` 是每次随机的 nonce）。
- **明文源码**只放在作者本机：`~/Downloads/dushen-private/`。这个目录不在任何 Git 仓库里。里面包括：
  - `net-online.js`（明文源码）；
  - `keys.json`（签名私钥、公钥、K）；
  - 封装工具用的说明。
- **封装工具** `tools/seal.mjs`（Node）：
  - 用法：`node tools/seal.mjs <明文路径> <keys.json 路径>`，生成 `js/net-online.enc.js`；
  - 工具本身在公开仓库里，不包含任何密钥。
- **联机中途卡过期**【我定的】：
  - 页面刷新时，如果保存的卡已过期，但本机有一个房间存档（房主的 `holdem-host` 或客人的 `holdem-session`），并且存档是在卡有效期内保存、距今不到 2 小时，仍然允许解密，只用来恢复这个房间，让这一场能打完；
  - 想新建或加入房间，必须是有效的卡。
- **运行时**：
  1. 卡密验证通过后，用卡密里的 K 解密；
  2. 把解出来的源码作为一个 `<script>` 插入页面，在全局作用域执行，定义出联机函数；
  3. 页面打开时如果 localStorage 里有有效的卡，就先自动解密，再执行现有的「刷新后恢复房间」逻辑；没有有效的卡时，跳过恢复。
- **打包**：`tools/bundle.py` 打包时包含 `net-online.enc.js`（是密文），不包含明文。
- **测试**【我定的】：
  - 直接调用联机函数的测试（现在 `tools/ddz-test.js` 里的联机部分）移到 `dushen-private/online-test.js`，不放在公开仓库；
  - 公开仓库里的 `tools/ddz-test.js` 只保留规则、牌局流程和卡密的测试；
  - 设计文档和计划里只有测试片段，没有联机实现代码，保留在仓库里。

## 6. 互相检查卡密

- 客人加入时，在 `hello` 消息里带上自己的卡号和卡密。房主用公钥验证签名，并用房主自己的设备时间判断有没有过期。无效时回复 `{t:'card-bad'}` 并断开连接，客人看到「卡密无效或已过期」。
- 房主在大厅消息和对局开始时带上自己的卡号和卡密，客人用同样的方法验证；无效时客人主动断开连接，并显示提示。
- **对局中有卡过期**【我定的】：
  - 已经开始的这一场照常打完，不中途踢人；
  - 对局中客人重连回自己原来的座位时，即使卡已过期，房主也放行；
  - 新加入的人（包括中途排队等座的）必须是有效的卡；
  - 下一次创建或加入房间时才拒绝过期的卡；房主的卡过期后，不能再开新的一场。
  - 对局中按名字重连（换了身份 ID）时，必须是有效的卡；只有身份 ID 相同的重连才能免检。
- 局域网模式同样检查。
- 卡号会显示在大厅里每个玩家的名字后面，方便房主确认来的是谁【我定的】。

## 7. 生成器

- 一个独立的 HTML 文件：`~/Downloads/赌神卡密生成器.html`。不放进仓库，点开就能用，作者不分享给别人。
- 第一次实现时由 Claude 生成密钥，写进生成器和 `dushen-private/keys.json`。生成器内嵌私钥、公钥和 K。
- 页面功能：
  - 输入卡号，选择有效期（天数，或者到期日期和时间），点「生成」，显示卡号和卡密，并各带一个复制按钮；
  - 「验证」：粘贴卡号和卡密，检查是否有效、什么时候到期；
  - 生成记录保存在生成器自己的 localStorage 里：卡号、到期时间、生成时间，方便作者查看发过哪些卡。
- 页面上醒目提示：「这个文件里有私钥，不要分享；丢失后无法再生成卡密，请备份」。
- **换密钥**【我定的】：第一版不做换密钥按钮。需要换的时候让 Claude 重新生成密钥、生成器和加密文件。

## 8. 清理公开仓库里的明文联机代码

用户选了「删仓库重建」。原因：
- 最早几次提交把整个游戏放在一个 `index.html` 里，里面就有明文联机代码，只删 `js/net.js` 删不干净；
- GitHub 会为每个 PR 永久保留旧提交，改写历史再强制推送也删不掉。

步骤：
1. 在 `dushen-private/` 里用 `git bundle` 备份完整的仓库，包括所有分支和历史，可以随时恢复。
2. 本机新建一条没有历史的分支，只包含加密后的当前版本：
   - 没有明文 `net.js`；
   - 没有联机测试；
   - 不包含旧的 `index.html` 单文件版。
3. 作者在 GitHub 上删除 `dushen` 仓库，用同一个名字重新创建（公开），并重新开启 GitHub Pages。这一步由作者自己操作，Claude 不做。
4. Claude 把这一个提交推送到新仓库的 `main`。
5. 删除仓库、推送新仓库前，各单独再确认一次。

要让作者知道的代价：
- 旧的 PR 记录（#1–#13）会全部消失；
- 已经被别人克隆或复刻（fork）的副本删不掉；
- 本机 `dushen` 文件夹的 Git 历史也会换成新的这一个提交，旧历史只保留在备份里。

## 9. 测试和验收

- **Node 测试**（`tools/card-test.js`，联机部分在本机的 `online-test.js`）：
  - 卡密能生成、验证；
  - 改动卡号、有效期或 K 中任意一个字节都会验证失败；
  - 过期的卡失效；
  - 设备时间被调回时失效；
  - 加密后再解密能得到原文；
  - 用错误的 K 解密会失败。
- **浏览器测试**：
  - 单机不受影响；
  - 第一次联机要求输入卡号和卡密，输错时提示错误，输对后能创建房间；
  - 刷新页面后自动恢复房间；
  - 客人的卡无效时被房主拒绝；房主的卡无效时客人主动断开；
  - 卡过期后提示重新输入；
  - 互联网和局域网都能正常联机；
  - 现有的联机回归全部通过；
  - 公开仓库的文件里没有联机实现代码，比如搜不到 `function hostOnMsg` 这样的函数定义；设计文档里提到函数名不算。
  - 在不支持浏览器加密功能的环境里，也能正常验证卡密、解密并联机：测试时把 `crypto.subtle` 去掉。
