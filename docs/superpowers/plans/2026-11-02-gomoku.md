# 五子棋 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增第五个玩法「五子棋」：15×15、黑棋禁手开关、四档电脑、教练标出前 3 个候选点并讲清依据、单机悔棋和联机申请悔棋，只记胜负盘数。

**Architecture:**
- 规则和棋局流程放在新文件 `js/games/gomoku.js`（仿照 `js/games/hongzhong.js` 的写法），棋力引擎放在 `js/games/gomoku-ai.js`，教练放在 `js/games/gomoku-coach.js`。
- 引擎写成一个自包含的函数 `gmAiModule()`，返回搜索接口。浏览器里把它的源码拼成 Blob 交给 Web Worker 运行，不卡界面；Worker 建不起来（例如某些 file:// 打开方式）就退回同步计算。Node 测试直接调用 `gmAiModule()`。
- 接入方式和红中麻将一样：引擎、界面里各处 `isM(...)` 分支旁边加 `isG(...)`；客人操作走统一入口 `act(p,type,to)`。加密联机核心的客人操作白名单需要加五子棋的新操作（Task 7）。

**Tech Stack:**
- 纯 HTML/CSS/JS，没有构建步骤，所有 `<script>` 共用全局作用域；不引入新的外部依赖。
- 测试：Node `vm` 单元测试；`tools/layout-check.mjs` 无头 Chrome 布局检查。

**Spec:** `docs/superpowers/specs/2026-11-02-gomoku-design.md`

**规则（照抄设计文档）**
- 15×15，黑先，横竖斜连成 5 个赢。不开禁手时长连（6 个以上）也算赢；开禁手时白棋长连算赢，黑棋长连是禁手。下满算和棋。
- 「黑棋禁手」开关默认关。打开后黑棋不能下三三、四四、长连；同时成五算赢不算禁手。判定按完整连珠规则（真活三要递归判断）。禁手点直接不让下，提示「禁手：三三 / 四四 / 长连」。白棋没有禁手。
- 第一局：单机手动选「我执黑先下 / 电脑执黑先下」；联机随机。之后：上一局输的一方执黑，和棋交换黑白。
- 悔棋：
  - 单机：轮到自己时随时可悔，撤回自己上一步和电脑的应手，不限次数。
  - 联机：只有在自己刚下完、对方还没落子时能申请；对方同意才悔；15 秒不回应算不同意；每人每局最多 3 次；申请挂着时对方倒计时暂停、不能落子；对方托管或掉线时申请直接算不同意。
  - 一局结束后不能悔棋。
- 超时：按教练建议落子并进入托管（不看「超时后采用教练方案」）。
- 认输：算对方赢一盘。
- 只记每人赢、输、和的盘数，不动筹码。
- 电脑难度：简单 / 普通 / 困难 / 地狱，默认普通，只在单机出现。思考时间上限：困难 1 秒、地狱 2 秒。
- 教练：始终用地狱同一个引擎；棋盘上绿色虚线圈标 ①②③；面板写建议、候选列表（坐标、评分、理由）和「怎么算的」（推算几步、检查了多少局面、棋型评分表）。
- 教练开关沿用「开启教练建议」；例外：玩家名以 lwx 结尾（不分大小写，只看末尾）时，关了也给这名玩家自己开教练。例外只适用于德州和五子棋。
- 联机房间固定 2 个座位，必须 2 名真人，不补电脑；「修改对局设置」时真人多于 2 人不能改成五子棋。

**速度（用户要求）**
- 迭代时只跑相关场景：`LC_ONLY=<场景> node tools/layout-check.mjs`。
- 提交前完整跑一次布局检查，加上全部 Node 测试，不重复跑。

## Review Focus

1. **不是自己回合、点到已有棋子的位置、电脑还在思考时连点**：不会落子、不会下两步。由 Task 3 的 `gm-place-guard` 用例覆盖。
2. **电脑思考时悔棋或认输**：Worker 稍后返回的旧结果必须作废（用 `seq` 比对），不能在新局面上落子。由 Task 3 的 `gm-stale-ai` 用例覆盖。
3. **客人发来非法落子**（越界、非整数、已占用、禁手点、不是他的回合）：拒绝，棋局不卡住。由 Task 3 的 `gm-bad-input` 用例覆盖。
4. **开禁手时黑棋只剩禁手点可下**：判和棋，不卡死。由 Task 1 的 `gm-black-stuck` 用例覆盖。
5. **悔棋申请挂着时申请人掉线、或对方掉线**：15 秒后照常超时算不同意，倒计时恢复，棋局继续。由 Task 3 的 `gm-undo-disc` 用例覆盖。
